高并发线程池

High Concurrency Thread Pool Module

在面对千万级请求时，如果为每个 HTTP 连接单独创建和销毁线程，内核上下文切换的开销将迅速榨干系统 CPU。为了将算力集中在业务处理上，我们需要一个强悍的“任务调度中心”。

本项目构建了一个基于 半同步/半反应堆 (Half-Sync/Half-Reactive) 并发模型的全局线程池，具备极高的吞吐量与线程安全性：

  • C++11 现代化并发封装： 摒弃了古老的 POSIX pthread 库，全面采用现代 C++ 的 std::thread 进行线程创建。利用 std::mutex 互斥锁与 std::condition_variable 条件变量，实现了极其优雅的线程挂起与唤醒机制。
  • 高安全性的任务请求队列： 主线程作为“生产者”，将 Epoll 监听到的就绪请求（HTTP 连接任务）无锁/加锁推入 std::list 请求队列；工作线程作为“消费者”，通过竞争机制获取任务，完美解决并发条件下的数据竞态（Race Condition）问题。
  • Reactor / Proactor 双驱调度： 线程池设计兼容两种顶尖的 I/O 模型。在 Reactor 模式下，工作线程负责完整的读写与业务逻辑；在 Proactor 模式下（借助模拟异步 I/O），主线程完成数据搬运，工作线程专注于 CPU 密集的业务计算，将分工做到极致。
  • 资源预分配与复用： 服务器启动时一次性初始化固定数量的工作线程（如 8 线程），线程在循环中处于休眠等待状态，任务到来时瞬间苏醒，彻底消灭了线程启停带来的高昂开销。
